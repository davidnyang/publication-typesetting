# 公开预览与同行反馈

仅在维护者提出公开技能、发布演示或邀请评价时加载。不把普通客户委托自动扩展成公开项目。

## 可审阅候选先行

从逐项核过来源的白名单文件建立全新目录，仅放自有通用方法、空白模板及获准合成示例；不直接把原私库改公开，不带其Git历史。排除客户稿件、刊物模板、人员信息、字体文件、软件安装包、私有路径、登录资料及内部评测答案；连文件名、元数据、嵌入资源也要核。

候选说明真实定位：工作流技能依赖宿主、合法软件/字体和实际控制通道，不自带桌面能力。写明确已实测的系统/应用版本、具体动作和未验证项。合成演示和文字决策检查不能称真实跨刊物终验。

先形成可审阅的具体文件包及清单，再确定仓库名、公开范围、自有代码/文字的许可证、署名和第三方依赖。许可证未定不称已经开源，不替客户或第三方授权。取得维护者对具体发布的明确决定后才新建公开库/上传；发布后回读实际公开树和字节。泛泛讨论想法不等于这些外部操作已经获准。

## 评价要能定位问题

用Issue表单收集：技能版本、模型/宿主、操作系统、应用实际版本与保存版本、任务类型、合成输入、复现步骤、实际结果、预期结果、失败位置和脱敏证据。保留首次失败及修订，未做项标未执行。不索取真实客户原稿、账号、私有路径或完整内部日志。

可设置五项1—5分的主观评分：说明清楚、接稿完整、软件操作可复现、审校有帮助、交付有帮助；每项保留“不适用/未执行”。另列完整文字、无缺字/溢文、阅读顺序、原生重开、PDF检查等必需项的通过/失败/未执行，以及实际操作与返工时间。主观平均分不能抵消技术失败，模型回复也不代表应用实测。

GitHub Star用于关注、收藏或赞许，不是排版质量评级。先用少量合格体验者的合成任务检验可复现性；自愿反馈存在选择偏差，真实跨刊物能力仍须新刊项目验证。评分、曝光和商业收益未知，不保证好评或效果。只有后续有相同条件和真实结果，才能比较版本效果。

表单文件本地创建不等于GitHub已启用；不要替维护者联系他人或自动邀请试用。
